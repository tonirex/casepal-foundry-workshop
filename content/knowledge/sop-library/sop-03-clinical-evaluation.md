# SOP-03 · Clinical Evaluation Report — Adequacy Check

**Version:** 2.1
**Owner:** Health Products Regulation Group · Medical Devices Branch
**Effective:** 1 July 2024

> **Synthetic content for the CasePal Foundry workshop.**

## 1. Purpose

Define what constitutes an adequate Clinical Evaluation Report (CER) in the registration dossier of a Class B, C, or D medical device.

## 2. When a CER is required

- **Class A** — not required.
- **Class B** — required if the device makes a *quantitative* clinical measurement (e.g. IVD reagents, monitors). Optional otherwise.
- **Class C** — always required.
- **Class D** — always required, plus a full clinical investigation report where the CER cites clinical data generated by the applicant themselves.

## 3. Minimum CER content

Every acceptable CER must include:

- **A. Scope statement** — indication for use, target population, contra-indications.
- **B. State-of-the-art review** — a survey of the current clinical management pathway the device is meant to support.
- **C. Clinical data sources** — one or more of: literature (systematic search + appraisal), equivalent-device data (with an equivalence argument), clinical investigation (own data).
- **D. Benefit-risk analysis** — quantified where possible, qualitative where not; must reference the risk-management file (ISO 14971 alignment).
- **E. Post-market plan** — link to the Post-Market Surveillance (PMS) plan; for Class D also the Post-Market Clinical Follow-up (PMCF) plan.

## 4. Special note — AI-MD / SaMD clinical evaluation

For AI-based medical devices, the CER must additionally address:

- **Training-data provenance** — what data was the model trained on? Is it representative of the intended population?
- **Validation methodology** — hold-out test set characteristics, performance metrics with confidence intervals.
- **Real-world performance monitoring** — how the applicant will detect model drift post-market.
- **Model version binding** — which version of the model is being registered; how upgrades will be handled.

If any of the AI-MD subsections is absent, the recommendation is *"query the applicant for the missing AI-validation subsection"*. Do NOT recommend rejection on first-pass absence — this is a rapidly-evolving space and clarification is normally productive.

## 5. Common adequacy failures (to flag in CasePal extraction)

| Failure mode | Reviewer action |
|---|---|
| No systematic literature search documented | Query — request search strategy + results |
| Equivalent-device claim without equivalence argument | Query — request equivalence justification per §3C |
| Benefit-risk qualitative only, when quantifiable metrics exist | Query — request quantification |
| Class D dossier citing only literature (no own clinical investigation) | Query — flag potential inadequacy |
| AI-MD without training-data provenance | Query — see §4 |

## 6. Reviewer discretion

CasePal flags adequacy concerns; the Reviewer decides whether to query or accept with condition. CasePal never autonomously determines a CER is *fatally* inadequate.
