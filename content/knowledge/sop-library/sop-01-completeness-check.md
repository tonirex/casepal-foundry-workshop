# SOP-01 · Medical Device Registration Dossier — Completeness Check

**Version:** 3.2
**Owner:** Health Products Regulation Group · Medical Devices Branch
**Effective:** 1 January 2024

> **This SOP is entirely synthetic and produced for the CasePal Foundry workshop.** No real Agency SOP is depicted.

## 1. Purpose

Define the minimum set of documents that must accompany a medical-device registration dossier before it can enter substantive technical review.

## 2. Scope

All incoming registration dossiers (new registration, variation, renewal) for medical devices classified as A / B / C / D per SOP-02.

## 3. Required documents by risk class

### 3.1 Class A (low risk)

- Application form (fully completed)
- Product information sheet
- Labelling (primary + secondary)
- Manufacturer declaration of conformity
- Applicant credentials (dealer's licence reference or manufacturer identity documents)

### 3.2 Class B (low-moderate risk)

All Class A requirements plus:

- Risk classification rationale (self-declared with justification)
- Design and manufacturing summary
- **Precision, accuracy, and repeatability data** (where measurement is claimed)
- Instructions for use (final version)
- Post-market surveillance plan (in-principle)

### 3.3 Class C (moderate-high risk)

All Class B requirements plus:

- **Clinical evaluation report (CER)** per SOP-03
- Risk-management file summary (ISO 14971-aligned)
- Software life-cycle documentation (where applicable — see SOP references to SaMD basics)
- Biocompatibility summary (where patient-contact)
- Sterilisation validation (where sterile)

### 3.4 Class D (high risk)

All Class C requirements plus:

- Full clinical investigation report (where CER references clinical data generated by the applicant)
- Cybersecurity risk assessment (for connected devices)
- Post-market clinical follow-up (PMCF) plan
- Long-term stability / durability data
- Independent third-party audit summary (where mandated)

## 4. Missing-document handling

- If a required document for the declared risk class is **absent**, the recommendation is normally *"query the applicant"* (not *"reject"*). Reject is only the recommendation where the applicant is unwilling or unable to submit the missing artefact after two RFI cycles — this is not for CasePal to determine autonomously.
- If a document is present but incomplete, cite the specific incompleteness — do not treat as absent.

## 5. Interaction with other SOPs

- Risk-class determination: **SOP-02**
- Clinical-evaluation adequacy: **SOP-03**
- Prior-similar-case check: **SOP-04**
- Query letter drafting: **SOP-05**

## 6. Reviewer discretion

Nothing in this SOP overrides the Product Reviewer's professional judgement. CasePal outputs are advisory. All accept / query / reject recommendations require reviewer sign-off in the Case Management System (see Lab 5 MCP integration).
